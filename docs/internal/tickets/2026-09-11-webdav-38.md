# GitHub #38：回收站同步 CONFLICT 循环与界面崩溃

https://github.com/dolag233/Serpent/issues/38

设计：`docs/internal/implementation/2026-09-11-webdav-sync-followups.md` §5.2

## 现象

已同步资产进回收站后 `sync.run` 报 `RemoteStorageError: CONFLICT`。永久删除或再导入仍 CONFLICT。`media.get-artifact-paths` 对缺失 artifacts 抛 `ASSET_NOT_FOUND`。渲染 `TypeError: e.trim is not a function`，界面不可用。

## 根因

`syncSnapshot` 不含回收站行，规划 `delete-remote` + 墓碑是对的。单条 HTTP 409 让整次同步失败且不写回 manifest。再导入撞上远端旧路径会再 PUT 409。缺缩略图文件被当成资产不存在。Renderer 对非字符串 `.trim()`。

## 应对

- 远端已无文件视为删除成功；单资产失败不中断整次会话。
- 同路径被另一 `syncId` 占用时先墓碑旧条目。
- 缺 artifact 重建，不用 `ASSET_NOT_FOUND` 表示缩略图没了。
- `toMessage` / 同步错误文案防护非字符串。
- 同步设置提供「用远端清单重置本地基线」（只重写 cache）。完整强制本地/云端仍归 `Serpent-871f34`。

不要做插件目录同步、不要做云回收站浏览 UI。

## 验证

plan/runner/engine 定向 + Renderer `toMessage`。改 library-service 必须 `npm run test:library-availability`。验收 ID：`SYNC-TRASH-001`。
